## 1. 积分规则（Points）

| 编号 | 规则 | 类型 |
|---|---|---|
| BR-PT-01 | 双轨积分：成长积分（growth）只增不减、决定等级、不可消费；兑换积分（exchange）可增可减、可消费、不参与等级判定。两轨独立，互不转换。 | 🔒 |
| BR-PT-02 | 参与活动完成：成长 +120（ACTIVITY_JOIN）、兑换 +50（ACTIVITY_JOIN_E）。数值 | 🔧 |
| BR-PT-03 | 发起活动获批/结束：发起人成长 +300（ACTIVITY_LAUNCH）。 | 🔧 |
| BR-PT-04 | 取消「已通过」报名：扣成长 -50（CANCEL_APPROVED）。取消「待审核」报名不扣分。 | 🔧 |
| BR-PT-05 | 每日签到：兑换 +10（DAILY_LOGIN），每自然日限一次。 | 🔧 |
| BR-PT-06 | 管理员手动调整（ADMIN_ADJUST）：可对任一轨道增减，必须填原因，写流水并记 operator_id。 | 🔒 机制 / 🔧 数值 |
| BR-PT-07 | 任何积分变动必须在同一事务内：写 point_log（append-only）+ 更新 users 冗余余额 +（成长分变动时）重算等级。 | 🔒 |
| BR-PT-08 | 余额不可为负：扣减后若 < 0 则整体拒绝（exchange 兑换、growth 扣分均适用）。 | 🔒 |
| BR-PT-09 | 内置规则（is_system）不可删除，仅可调值/启停；停用后该场景不再发分。 | 🔒 |
| BR-PT-10 | 流水文案与余额快照（balance_after）随每条记录持久化，用于对账，不依赖实时求和。 | 🔒 |

## 2. 等级规则（Level）

| 编号 | 规则 | 类型 |
|---|---|---|
| BR-LV-01 | 五级：萌新(0) / 同行者(500) / 实践家(1500) / 布道者(4000) / 核心(9000)，按累计成长分自动晋级。 | 🔧 阈值 |
| BR-LV-02 | 晋级进度 = (当前成长分 − 当前等级下限) / (下一等级下限 − 当前等级下限) × 100%；最高级恒显 100%「已达最高等级」。 | 🔒 公式 |
| BR-LV-03 | **不降级原则**：管理员调高阈值后，存量会员等级保持不变，仅影响后续晋升判定。等级只随新的成长分增加而上升，永不因配置或扣分而自动下降。 | 🔒 |
| BR-LV-04 | 「可申请发起人」由等级的 can_apply_launcher 决定（默认同行者起）。 | 🔧 |
| BR-LV-05 | 晋级实时结算（成长分变动后即时），无需手动领取；可触发等级类徽章与通知。 | 🔒 |

## 3. 活动规则（Activity）

| 编号 | 规则 | 类型 |
|---|---|---|
| BR-AC-01 | 仅 LAUNCHER 可创建活动；活动归属其发起人（launcher_id）。 | 🔒 |
| BR-AC-02 | 草稿保存宽松校验：仅 title 必填。提交审核全量严格校验：title(1-100)、category、summary(1-200)、location(≤200)、content(去标签≥20字)、start/end/deadline、max_participants(1-10000)。 | 🔒 |
| BR-AC-03 | 时间逻辑：registration_deadline < start_time < end_time，且均晚于当前时间。 | 🔒 |
| BR-AC-04 | 活动状态机见 STATE_MACHINE §1；各状态可用操作严格受限，非法转换拒绝。 | 🔒 |
| BR-AC-05 | 危险操作二次确认：取消活动 / 结束活动 / 开始活动，均需弹窗确认并提示后果。 | 🔒 |
| BR-AC-06 | 结束活动对所有 APPROVED 报名者发分（BR-PT-02/03），幂等防重。 | 🔒 |
| BR-AC-07 | 取消活动通知所有已报名者；不发分、不扣分。 | 🔒 |
| BR-AC-08 | min_level_id 为报名等级门槛，NULL=无限制。 | 🔧 单活动 |
| BR-AC-09 | 自动流转：到 start_time 自动开始、到 end_time 自动结束（定时任务），与手动操作幂等共存。 | 🔧 开关 |

## 4. 报名规则（Registration）

| 编号 | 规则 | 类型 |
|---|---|---|
| BR-RG-01 | 同一活动同一用户不可重复有效报名（PENDING/APPROVED 唯一）。 | 🔒 |
| BR-RG-02 | 名额控制用乐观锁：审批通过时 `UPDATE ... WHERE approved_count < max_participants`，命中才通过，否则报「名额已满」。 | 🔒 |
| BR-RG-03 | 报名前置：活动 REGISTRATION_OPEN、未过 deadline、用户等级≥门槛、名额未满、用户 ACTIVE。 | 🔒 |
| BR-RG-04 | 报名即 PENDING，由发起人审批，不自动通过。 | 🔒 |
| BR-RG-05 | 拒绝报名必须填原因（≤500 字），并通知报名者。 | 🔒 |
| BR-RG-06 | 取消报名：仅 PENDING/APPROVED 可取消；APPROVED 取消扣 50 成长分（BR-PT-04）并二次确认+释放名额，PENDING 取消不扣分。 | 🔒 |
| BR-RG-07 | 活动进入 IN_PROGRESS 后报名通道关闭，不再接受新报名。 | 🔒 |

## 5. 福利规则（Reward）

| 编号 | 规则 | 类型 |
|---|---|---|
| BR-RW-01 | 兑换前置：用户 ACTIVE、exchange_points≥cost、reward ON_SHELF、stock>0。 | 🔒 |
| BR-RW-02 | 兑换为单事务：扣兑换积分 + 扣库存 + 建订单 + 写流水，任一失败整体回滚（BR-PT-08）。 | 🔒 |
| BR-RW-03 | 按钮态：积分足→「立即兑换」；积分不足→提示差额不可提交；库存0→「已售罄」禁用；已下架→不展示。 | 🔒 |
| BR-RW-04 | 订单 cost 为下单时快照，福利改价不影响历史订单。 | 🔒 |
| BR-RW-05 | 福利的 cost/stock/category/上下架由管理员维护。 | 🔧 |
| BR-RW-06 | 实践家及以上「福利 8 折」为等级特权——本期作为可选项，若启用则结算价 = ceil(cost × 等级折扣)。 | 🔧（默认关闭） |

## 9. 可配置项 vs 系统固定 · 速查

**🔧 可配置（后台无需发版）**：各积分规则数值与启停、等级阈值/名称/特权/可申请发起人开关、福利的价格/库存/分类/上下架、资料完善奖励值、活动自动流转开关、福利折扣特权开关、通知订阅项、单活动的等级门槛。

**🔒 系统固定（改动需发版）**：双轨积分语义、积分事务一致性、余额非负、等级进度公式、不降级原则、活动/报名/申请/订单状态机、唯一性约束（重复报名、并发申请）、乐观锁名额控制、统一驳回机制、注销 30 天宽限、上传限制、权限与所有权校验。
