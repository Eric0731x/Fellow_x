## 2. 必须补充（Must-have · 阻塞开发，需在 Phase 0–1 前确认）

1. **冻结术语枚举**：确认采用「萌新/同行者/实践家/布道者/核心」五级及阈值（已裁定，需产品签字）。
2. **确认积分数值**：CANCEL_APPROVED = -50、完善资料 +5、签到 +10 等以 BUSINESS_RULES 为准签字（消除 -5/-50 歧义）。
3. **确认报名审批模型**：报名为「待审核→发起人审批」而非即时通过（BR-RG-04）。
4. **环境与密钥**：DB 连接、对象存储（头像/封面）、短信服务（注册验证码）三项外部依赖的凭据与 SLA。
5. **Admin 账号来源**：管理员如何产生（后台预置/运维分配），不可自助注册。
6. **技术栈已冻结**（见 TECH_STACK.md）：前端 React+TS+Vite+AntD、后端 NestJS+Prisma、库 PostgreSQL；移除 Vue 备选，避免 Agent 摇摆。

## 3. 建议补充（Should-have · 影响质量，建议 Phase 内补齐）

1. **测试夹具契约**：为每个状态机转换与并发场景（名额/库存/重复）准备可复用种子与用例数据。
2. **统计口径定义**：参与天数、连击中断规则、仪表盘环比的计算窗口。
3. **富文本白名单**：content 允许的标签/属性清单（XSS 防护，R8）。
4. **限频策略**：短信、登录、兑换、上传的频控阈值（R9/R10）。
5. **通知投递通道**：站内信为主，是否对接小程序订阅消息/公众号模板（BR-NT-01 订阅项）。
6. **非功能指标**：列表 P95 延迟目标、并发量级、数据量级，用于索引与缓存决策。
